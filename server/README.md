# Server Module

Java backend for the Velocity Template Editor extension. Provides 100% Apache Velocity-compatible template rendering via HTTP API using Apache Velocity 2.3 and GraalVM JavaScript for method mocks.

## Architecture

```
server/
├── pom.xml                          # Maven build configuration
├── dependency-reduced-pom.xml       # Generated by Maven Shade Plugin
├── src/main/
│   ├── java/com/ktmoyakhe/vscode/velocity/
│   │   ├── VelocityServer.java      # Main HTTP server & entry point
│   │   ├── handler/
│   │   │   ├── HealthHandler.java   # GET /health endpoint
│   │   │   ├── RenderHandler.java   # POST /render endpoint
```

## API Endpoints

### POST /render
Render a Velocity template with variables and method mocks.

**Request:**
```json
{
  "template": "#set($name = 'World')\nHello $name!\n$user.getName()",
  "variables": {
    "user": {
      "name": "John",
      "age": 30,
      "email": "john@example.com"
    },
    "config": {
      "siteUrl": "https://example.com"
    }
  },
  "methods": {
    "user": {
      "getName": {
        "name": "getName",
        "implementation": "return 'John Doe'"
      },
      "getEmail": {
        "name": "getEmail",
        "implementation": "return args[0] ? args[0] : 'no-reply@example.com'"
      }
    },
    "utils": {
      "formatDate": {
        "name": "formatDate",
        "implementation": "return new Date().toISOString().split('T')[0]"
      }
    }
  },
  "mockHeaders": {
    "User-Agent": "Mozilla/5.0",
    "Accept-Language": "en-US"
  },
  "mockUrl": "https://example.com/page",
  "httpServletRequestVar": "request",
  "locale": "en_US",
  "localeVar": "locale",
  "messagesPropertiesPath": "/path/to/messages.properties",
  "templateMessagesVar": "messages",
  "escapeToolVar": "esc",
  "utilsVar": "utils"
}
```

**Response (200 OK):**
```
Hello World!
John Doe
```

**Error Response (400 Bad Request):**
```json
{
  "error": "Template parsing error",
  "details": "Encountered \"<EOF>\" at line 1, column 10",
  "stackTrace": "..."
}
```

**Request Fields:**
- `template` (required): Velocity template string
- `variables` (optional): Context variables as JSON object
- `methods` (optional): JavaScript method implementations
- `mockHeaders` (optional): HTTP headers for $request mock
- `mockUrl` (optional): URL for $request.getRequestURL()
- `httpServletRequestVar` (optional): Variable name for $request (default: "request")
- `locale` (optional): Locale string (e.g., "en_US", "fr_FR")
- `localeVar` (optional): Variable name for $locale (default: "locale")
- `messagesPropertiesPath` (optional): Path to .properties file for i18n
- `templateMessagesVar` (optional): Variable name for $messages (default: "messages")
- `escapeToolVar` (optional): Variable name for $esc (default: "esc")
- `utilsVar` (optional): Variable name for $utils (default: "utils")

## Core Components

### VelocityServer.java
**Purpose:** Main HTTP server and application entry point

**Key Features:**
- Creates HTTP server on port 9876 (configurable)
- Registers endpoint handlers: `/render`, `/health`, `/shutdown`
- Initializes Apache Velocity engine with custom configuration
- Provides GraalVM Polyglot context for JavaScript execution
- Thread pool executor for handling concurrent requests

**Configuration:**
```java
VelocityEngine engine = new VelocityEngine();
engine.setProperty("resource.loaders", "string");
engine.setProperty("resource.loader.string.class", 
    "org.apache.velocity.runtime.resource.loader.StringResourceLoader");
engine.setProperty("runtime.introspector.uberspect", 
    "com.ktmoyakhe.vscode.velocity.introspection.CustomUberspect");
```

### handler/RenderHandler.java
**Purpose:** Processes POST /render requests

**Responsibilities:**
1. Parse JSON request body (template, variables, methods)
2. Create Velocity context with variables
3. Register JavaScript method mocks via `CustomUberspect`
4. Add utility objects: `$request`, `$locale`, `$messages`, `$esc`, `$utils`
5. Merge Velocity template with context
6. Return rendered HTML or error details

**Error Handling:**
- Catches `ParseErrorException` for template syntax errors
- Catches `MethodInvocationException` for runtime errors
- Returns HTTP 400 with detailed error messages and stack traces

### handler/HealthHandler.java
**Purpose:** Health check endpoint for monitoring

Returns server status, version, and engine information.

### handler/ShutdownHandler.java
**Purpose:** Graceful server shutdown (for development/testing)

Stops HTTP server and exits JVM with status code 0.

### introspection/CustomUberspect.java
**Purpose:** Custom Velocity introspection for method resolution

**Key Features:**
- Extends `UberspectImpl` from Apache Velocity
- Intercepts method calls to check for JavaScript mocks
- Returns `MockVelMethod` if mock implementation exists
- Falls back to standard Java reflection if no mock found

**How It Works:**
```java
@Override
public VelMethod getMethod(Object obj, String methodName, Object[] args, Info i) {
    // Check if JavaScript mock exists for this method
    if (hasMock(obj, methodName)) {
        return new MockVelMethod(javascriptContext, mockImplementation);
    }
    // Otherwise use standard Java method
    return super.getMethod(obj, methodName, args, i);
}
```

### introspection/MockVelMethod.java
**Purpose:** Execute JavaScript method implementations in Velocity templates

**Key Features:**
- Implements `VelMethod` interface from Velocity
- Uses GraalVM Polyglot API to execute JavaScript code
- Passes method arguments to JavaScript via `args[]` array
- Returns JavaScript result back to Velocity template

**Example:**
```javascript
// Implementation in context:
"implementation": "return args[0].toUpperCase() + '!'"

// In template:
$user.getName("john")  // Calls JavaScript, returns "JOHN!"
```

**Error Handling:**
- Catches JavaScript syntax errors
- Catches runtime exceptions
- Returns error message as string in template

### mock/MockHttpServletRequest.java
**Purpose:** Mock HTTP request object for `$request` variable

**Key Features:**
- Implements common `HttpServletRequest` methods
- Returns mock data from extension context (URL, headers, parameters)
- Supports: `getRequestURL()`, `getHeader()`, `getParameter()`, etc.

**Usage in Template:**
```velocity
URL: $request.getRequestURL()
User-Agent: $request.getHeader("User-Agent")
Language: $request.getLocale().getLanguage()
```

### mock/MockObject.java
**Purpose:** Generic mock object wrapper for JavaScript methods

Wraps context variables and provides method lookup for JavaScript implementations.

### util/EscapeTool.java
**Purpose:** Escaping utilities for security (`$esc` tool)

**Methods:**
- `html(String)` - HTML entity encoding (`<` → `&lt;`)
- `xml(String)` - XML escaping
- `javascript(String)` - JavaScript string escaping
- `url(String)` - URL encoding

**Usage:**
```velocity
<div>$esc.html($userInput)</div>
<script>var name = '$esc.javascript($userName)';</script>
```

### util/LocaleHelper.java
**Purpose:** Locale support for internationalization (`$locale` object)

**Methods:**
- `getLanguage()` - Returns language code (e.g., "en")
- `getCountry()` - Returns country code (e.g., "US")
- `getDisplayName()` - Returns full name (e.g., "English (United States)")

**Usage:**
```velocity
Current language: $locale.getLanguage()
```

### util/TemplateMessages.java
**Purpose:** i18n message lookup from .properties files (`$messages` object)

**Key Features:**
- Loads messages from `.properties` files
- Supports parameterized messages (e.g., `welcome.message=Hello {0}!`)
- Falls back to key name if message not found

**Usage:**
```velocity
$messages.get("welcome.message", "John")  ## Output: Hello John!
```

### util/UtilsHelper.java
**Purpose:** Miscellaneous utility functions (`$utils` object)

**Methods (examples):**
- `formatDate(Date)` - Format dates
- `capitalize(String)` - Capitalize first letter
- `isEmpty(String)` - Check if string is null or empty

**Usage:**
```velocity
#if($utils.isEmpty($name))
  <p>Name is required</p>
#end
```

## Features

### ✅ Apache Velocity 2.3
- **100% official implementation** - Not a custom parser
- Full Velocity Template Language (VTL) support
- All directives: `#set`, `#if`, `#foreach`, `#macro`, `#parse`, etc.
- All operators: arithmetic, logical, comparison

### ✅ GraalVM JavaScript Engine
- Execute JavaScript code for method mocks
- Access method parameters via `args[]` array
- Full ES6+ syntax support
- Sandboxed execution for security

### ✅ Properties File Support
- Load `.properties` files for internationalization
- Parameter substitution: `message=Hello {0}!`
- Locale-aware message formatting

### ✅ HTTP Server
- Lightweight `com.sun.net.httpserver.HttpServer`
- No external web framework dependencies
- Fast startup (~2-3 seconds on cold start)
- Concurrent request handling with thread pool

### ✅ CORS Enabled
- `Access-Control-Allow-Origin: *`
- Works with VS Code webviews
- No cross-origin restrictions

### ✅ Error Handling
- Detailed error messages with line numbers
- Full stack traces for debugging
- Differentiates syntax errors vs runtime errors
- Returns HTTP 400 for user errors, 500 for server errors

### ✅ Utility Objects
- `$request` - Mock HTTP request with headers/parameters
- `$locale` - Locale information (language, country)
- `$messages` - i18n message lookup from .properties
- `$esc` - HTML/XML/JavaScript/URL escaping
- `$utils` - Miscellaneous utility functions

## Method Mocks

Method implementations use JavaScript (executed via GraalVM):

### Simple Value Return
```javascript
// Implementation:
"return 'Hello World'"

// Template:
$object.getValue()  ## Output: Hello World
```

### Using Arguments
```javascript
// Implementation:
"return args[0].toUpperCase()"

// Template:
$utils.upper("hello")  ## Output: HELLO
```

### Multiple Arguments
```javascript
// Implementation:
"return args[0] + ' ' + args[1]"

// Template:
$user.fullName("John", "Doe")  ## Output: John Doe
```

### Conditional Logic
```javascript
// Implementation:
"return args[0] ? 'Yes' : 'No'"

// Template:
$utils.boolToString(true)  ## Output: Yes
```

### Complex Logic
```javascript
// Implementation:
"const value = args[0] || 'default'; return value.toUpperCase()"

// Template:
$utils.normalize(null)     ## Output: DEFAULT
$utils.normalize("hello")  ## Output: HELLO
```

### Accessing JavaScript Built-ins
```javascript
// Implementation:
"return new Date().toISOString()"

// Template:
$utils.currentDate()  ## Output: 2026-02-22T10:30:00.000Z
```

## Logging

Uses **Log4j2** for structured logging. Configuration in `src/main/resources/log4j2.xml`.

### Log Files
- `server.log` - General application logs (INFO level)
- `server.err.log` - Error logs only (ERROR level)
- `server.out.log` - Standard output (DEBUG level)

### Log Levels
- **DEBUG**: Detailed request/response data
- **INFO**: Server startup, shutdown, request counts
- **WARN**: Non-fatal issues (e.g., missing optional fields)
- **ERROR**: Exceptions, failures, server errors

### Example Log Output
```
2026-02-22 10:30:15 INFO  [main] VelocityServer - Velocity Server starting on port 9876...
2026-02-22 10:30:17 INFO  [main] VelocityServer - Velocity Server is ready!
2026-02-22 10:32:45 DEBUG [pool-1-thread-2] RenderHandler - Rendering template (125 bytes)
2026-02-22 10:32:45 DEBUG [pool-1-thread-2] RenderHandler - Context variables: {user, config}
2026-02-22 10:32:45 INFO  [pool-1-thread-2] RenderHandler - Rendered successfully (342 bytes)
```

### Change Log Level
Edit `src/main/resources/log4j2.xml`:
```xml
<Configuration>
    <Loggers>
        <Root level="DEBUG">  <!-- Change to INFO, WARN, or ERROR -->
            <AppenderRef ref="File"/>
        </Root>
    </Loggers>
</Configuration>
```

- **VS Code extension compatibility** - Extension spawns single JAR process
- **Version consistency** - All dependencies bundled at specific versions

## Integration with Extension

The VS Code extension (`extension/velocityServerClient.ts`) communicates with this server:

### Server Lifecycle
1. Extension activates → Spawns Java process: `java -jar server/target/velocity-server-1.0.0.jar`
2. Wait for server ready (health checks with retries)
3. Extension uses server for template rendering
4. Extension deactivates → Sends POST /shutdown

### Communication Flow
```
extension/preview.ts
    ↓ (HTTP POST)
velocityServerClient.ts
    ↓ (JSON request)
server/handler/RenderHandler.java
    ↓ (Velocity template + context)
Apache Velocity Engine 2.3
    ↓ (Rendered HTML)
RenderHandler → HTTP response
    ↓
velocityServerClient.ts
    ↓
preview.ts → Display in webview
```

### Process Management
- **Working Directory**: `server/` folder (so logs are written there)
- **Output**: Captured by extension and logged to "Velocity Server" output channel
- **Error Handling**: Extension shows error notifications if server fails to start

## Performance Considerations

### Startup Time
- **Cold start**: ~2-3 seconds (loading JVM, GraalVM, Velocity engine)
- **Warm start**: ~1-2 seconds (if JVM already warm)

### Template Rendering
- **Simple templates**: <10ms
- **Complex templates** (loops, conditions): 10-50ms
- **Large contexts** (1000+ variables): 50-100ms

### Memory Usage
- **Base**: ~100MB (JVM + GraalVM + Velocity engine)
- **Per request**: ~5-10MB transient (GC'd after response)
- **Large templates** (>1MB): May require more heap

### Optimization Tips
1. **Increase heap size**: `java -Xmx512m -jar velocity-server-1.0.0.jar`
2. **Use G1GC**: `java -XX:+UseG1GC -jar velocity-server-1.0.0.jar`
3. **Reduce logging**: Set log level to WARN in log4j2.xml
4. **Reuse context**: Cache parsed templates if possible (future enhancement)

## Known Limitations

### GraalVM Context Isolation
- Each render request creates a new Polyglot context
- JavaScript state is not shared between requests
- No access to Java objects from JavaScript (by design)

### Method Mock Restrictions
- Cannot call Java methods directly from JavaScript
- Parameters must be JSON-serializable
- Return values must be primitives or JSON objects

### Template Size
- Very large templates (>10MB) may cause OutOfMemoryError
- Workaround: Increase heap size with `-Xmx` flag

### Concurrency
- Thread pool size is fixed (not configurable)
- High concurrency (100+ simultaneous requests) may cause queuing

## Security Considerations

### JavaScript Execution
- GraalVM Polyglot context is **sandboxed**
- No file system access from JavaScript
- No network access from JavaScript
- No access to Java reflection APIs

### Template Injection
- **User input should be escaped** before rendering
- Use `$esc.html()` tool for HTML output
- Use `$esc.javascript()` for JavaScript contexts

### Production Deployment
- **Not recommended for production** (designed for local development)
- If deployed:
  - Add authentication/authorization
  - Validate all inputs
  - Rate limit requests
  - Use HTTPS with reverse proxy

## Troubleshooting

### Server won't start
**Error:** `Address already in use`
**Solution:** Port 9876 is occupied. Change port:
```bash
java -Dvelocity.server.port=9877 -jar target/velocity-server-1.0.0.jar
```

### OutOfMemoryError
**Error:** `java.lang.OutOfMemoryError: Java heap space`
**Solution:** Increase heap size:
```bash
java -Xmx512m -jar target/velocity-server-1.0.0.jar
```

### GraalVM errors
**Error:** `Polyglot context error: ...`
**Solution:** Ensure GraalVM dependencies are in classpath (should be in fat JAR).

### Template parsing errors
**Error:** `Encountered "<EOF>" at line X`
**Solution:** Check Velocity syntax - likely unclosed directive or missing `#end`.

### Method not found
**Error:** `Method ... does not exist`
**Solution:** Ensure method mock is registered in the `methods` field of the request.
